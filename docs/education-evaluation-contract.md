# Contoso enrollment evaluation education-1.0.0

CU1-ENR-C/D are two controlled installations in a second domain family, based
on pinned jbogard/ContosoUniversity MVC5 source. They are not independent tasks
within that family. The public request, B-owned source pin and original raw
business SQLite are authoritative; `migration-oracle.json` contains independent
researcher-owned expected rows/enum interpretation and is excluded from worker
input. Calibration fixtures are development controls, not research hold-outs.

The ordinary evaluator has twelve executable checks, each connected to the
matching public requirement in the versioned C/D ledgers:

| Check | Actual observation |
| --- | --- |
| E-001 | .NET 8+ Web project publish and launched readiness |
| E-002 | Project dependencies and published managed metadata lack System.Web/.NETFramework execution references |
| E-003 | Missing target path: product imports raw Person/FirstName/singular source tables into plural target tables, preserving every specified original value/ID/FK |
| E-004 | Home links, Student list, ordinary Details/Edit links, name search IDs |
| E-005 | Student details, source FullName, course joins, source enum interpretation, null grade and missing-ID response |
| E-006 | Course IDs, title, credits, department joins and missing-ID response |
| E-007 | Valid Create persists one new noncolliding student and preserves originals |
| E-008 | Nine invalid Create requests: three missing fields, three whitespace fields, two names longer than 50, impossible calendar date; no table mutation |
| E-009 | Valid Edit of the newly created student persists only intended fields; original students/related tables preserved; unknown ID rejected |
| E-010 | The same nine invalid Edit cases preserve the database |
| E-011 | Confirmed old process stop, distinct restarted process, same database path, original and newly edited rows survive |
| E-012 | Actual browser Create, then visible Edit/Save; application navigation presents saved values and independent read-only SQLite agrees |

The initial ordinary scoring application receives only raw
`/inputs/existing-business/legacy-school.sqlite`; it is not preseeded with the
private derivative target database. The browser receives the derivative initial
state in a separate isolated database after E-003 has independently measured
import. HTTP checks submit ordinary form fields including hidden anti-forgery
tokens. The browser performs only visible form operations. Setup navigation to
Edit happens before the measured Save; the evaluator never forces a post-Save
reload/navigation or repairs product code.

Browser evidence binds instance/artifact/ledger, one tab and origin, ordered
capture timestamps, before/created/edit/after DOM, before/after screenshots,
browser/node/collector identity, trace, and an independent host SQLite result.
Absent/unsupported controls remain blocked. Observer faults remain evaluator
faults; previously confirmed product failures remain failures with incomplete
coverage. Known database import loss is a critical product failure with dependent
checks blocked. Cleanup status is recorded separately from quality. All owned
browser containers/networks have labelled intents and cleanup receipts.

The prepared nine-case manifest fixes expectations before any score: both
positive variants, incorrect fixed grade interpretation, incorrect raw column
mapping, missing name validation, nonfunctional visible Save, unsupported Save,
collector fault with known grade failure, and cleanup receipt fault with known
grade failure. `inner/calibration/migration-chain.py --education` uses ordinary
`score_run`, composition and aggregation. It records exact evaluator DLL/image,
all code/input/ledger/public contract hashes, each case result, and actual owned
cleanup confirmation. Preparation and final receipt paths are versioned rather
than overwriting old evidence. Final integrated calibration is still pending
until a receipt reports every predeclared expectation matched.

Human review is **not_run**. Reference packages and B's independent 52-check
HTTP/SQLite workflow are separate evidence, not human acceptance. The combined
human kit includes both task families and remains scoped to the actual asset
hashes. Authentication, instructors/administration, course/grade editing,
deletion, pagination/sorting, concurrency/performance and external integrations
are explicitly excluded. Numeric results describe these finite fixtures and
the two controlled families only.

The first integrated nine-case calibration at `artifacts/edu21-v1` matched
every predeclared verdict/state expectation. A subsequent targeted calibration
at `artifacts/edu21-v2-restart` preserved a mismatch: the restart baseline was
still sampled before invalid Edit requests. E-011 now captures the actual full
database immediately before the owned stop, while E-008/E-010 retain invalid
input failures. Expectations were not adjusted to the observed result.

Independent review also found that a later HTTP observer fault could erase an
already observed failure while checks were accumulated in local variables.
Each independent failure is now sticky, recorded immediately, and retained in
`observed-checks.jsonl`. Bound HTTP output from a nonzero evaluator exit is
preserved by ordinary scoring with numeric quality suppressed and coverage
incomplete. Two outer regression cases distinguish a bound known critical
failure from output claiming another artifact. The final declared subset has
normal C/D, invalid names (E-008/E-010 only), and an incorrect first-student grade
followed by a later HTTP timeout (E-005 remains critical, observer fault remains
incomplete). Other previously measured cases may be retained only with explicit
code/data dependency witnesses; they are not described as all running one DLL.
