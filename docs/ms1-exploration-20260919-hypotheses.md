## 主仮説の確定を保留する理由

優先順位はH2のカタログ原文保持である。しかし、今回の新規explainedにはモデル実行がなく、
条件内の反復もない。品質不合格が混じり、評価器にも偽不合格の具体例がある。
したがって、確認実験へそのまま進む主仮説1件の確定はしない。

不足しているのは、(1) 新規explainedを含む反復での取得・保持パターン、
(2) 全文のどの情報が実装に必要で、どれを機械処理だけで扱えるかの対応表、
(3) 品質判定の不一致の解決、(4) 人による主要シナリオの確認である。
環境障害を修正した後の新バッチで、固定した問いに沿って不足を埋める。
今回の中断バッチへ条件を変えて追加しない。

## H2を具体化する場合の比較案（未実装・未実行）

問いは「カタログの原文全件をモデル文脈へ入れずにファイル上で保持すると、必要な順序・IDを
保ったままRun全体のトークンを減らせるか」とする。起動ログ抑制やツールのまとめ方は同時に変えない。

| 項目 | 次に固定する内容 |
|---|---|
| 共通の準備 | 同じCompleted原本から、同じ決定的な抽出処理で順序付きデータを作る。モデル外での推測やLLM要約はしない。原本と抽出物を同じパス・同じバイト列で両条件へ供給する |
| 共通の情報 | 原本の所在・SHA-256・処理結果・10ジャンルの件数・246件・指定IDの検査結果・登録順を保った旨を、同一の短い出力として渡す。範囲指定で原文を取得する経路も両条件で同一にする |
| 変えるもの | 当該ツール結果に原文全件を併記する条件と、共通の短い出力のみを渡す条件。提示のタイミングとその他の出力は揃える |
| 固定するもの | タスク、要求、モデル、エージェント、予算、compaction、ソース、準備処理、ツール、原文アクセス、改版・校正済み評価器。新しい情報処理機能は両条件に同じものを与える |
| 主指標 | 全呼び出しのinput＋output、失敗・打切り・欠測を含む全試行。準備が決定的な非LLM処理ならLLM tokensは発生しないが処理方法と時間は記録する |
| 行動の予測 | 初期の大きな入力増分とその後の保持文字量が小さくなる。原文再取得・呼び出し数・後半修正が増えて効果を相殺しない |
| 反証となる観測 | 全文再取得で入力差が消える、追加の確認／修正で総量が減らない、必要なID・順序・文字列・購入挙動を失う、別の追加情報の有無だけで差が説明される |
| 品質条件 | 既存挙動・データ制約との対応を先に確認。原本の削除や勝手なソートはしない。要件の品質低下があれば効率改善と判定しない |

この比較は現行3条件の勝者選びではなく、観測された入力増加に対応する特定の変更を検証するもの。
短い出力側にだけ設計上のヒントを加えないことが重要である。
具体的な共通出力、取得手順と範囲、期待する必要事実は、確認用データを採る前に固定する。

## 確認実験の反復数と停止

今回は反復数を決めない。まず、実務上意味のある最小削減幅、許容する品質低下の上限
（低下を許さない場合はその判定法）、推定に必要な精度、総実行予算を定める。
その後に、ばらつきの保守的な範囲を使って、固定反復数で得られる精度や検出可能な差を検討する。
今回の各1観測や既存2件の削減率を真の効果量として採用しない。
解析法・順序・技術失敗の扱い・追加／停止規則を採取前に固定し、新しいRunだけで確認する。
途中の結果を見て有意になるまで追加しない。
[反復数の正当化](https://lakens.github.io/statistical_inferences/08-samplesizejustification.html)

## 先行研究との位置付け

タスクに必要な文脈を選別する問題は
[SWE-Pruner](https://arxiv.org/abs/2601.16746)でも扱われている。
本候補は、カタログの登録順・ID・注文挙動を保つモダナイズにおいて、データをファイルに保ち、
モデルへの提示範囲を変える場合の成立条件を調べる案である。
既知の選別効果の再現なのか、データ制約のある課題への拡張なのかは未確定で、
題材の違いだけを新規性とはしない。論文の削減率を今回へ移し替えない。
