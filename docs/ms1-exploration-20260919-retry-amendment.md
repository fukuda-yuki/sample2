# MS1 探索実験の再開記録（2026-09-19、改訂 R1）

ユーザーの「retry. また Dockerのネットワーク資源が枯渇したら，原因を特定し，修復できるか試してください」という追加指示に基づく。初回停止時の記録・凍結計画を残し、停止理由に限定した運用変更を適用する。これは探索中の変更であり、事前に予定された無中断バッチとは扱わない。

## 変更理由と処置

初回3枠目 explained-001 は、モデル呼び出し前の `docker network create` で `all predefined address pools have been fully subnetted` により停止した。初期観測では Docker ネットワークが32個あり、既定3個に加えて終了済みRun用26個・プレビュー用3個が残っていた。既存実行器はコンテナを停止するが、専用ネットワークを解放しないため、既定のサブネット割当が枯渇する。

現在のバッチの完了済み2 Runについて、アーカイブ検証・停止・所有ラベル・専用ネットワークID・接続先を照合し、使用中でない内部ネットワークのみ削除する。コンテナ、Run原本、成果物、アーカイブは保持する。他の実験資源やDocker全体のpruneは行わない。内部ネットワークの作成・削除で回復を確認し、この確認ではモデルを呼ばない。

以後は各Runの計測終了、停止、保存検証の後、同じ条件で専用ネットワークを回収する。モデル・評価器・イメージ・隔離方式・Run予算・通常CLI経路・ソース・投入内容は変更しない。回収は計測区間外の研究用運用処理である。

## 実行数と順序

- 完了した explore-001 / preload-001 は再実行しない。preload-001 の品質不合格も残し、補充対象にしない。
- explained-001 の環境失敗、usage欠測、元の停止判定を変更しない。
- 未実行の初回15枠（枠4–18）を元の順序で実行する。乱数seedとブロックは変更しない。
- 初回18枠の終了後、explained-001 に対応する補充を `MS1-001-explained-007` として実行する。元Runとは別集計し、元のブロック差へ代入しない。
- 追加指示による例外は、停止確認済み・モデル未呼び出し・原本に上記Dockerエラーがある障害に限定する。同じ障害が再発した場合も原因を確認し、回収と割当確認に成功した後のみ続行する。認証、利用枠、保存、固定条件の不一致、隔離検証の失敗などは引き続き停止する。
- 元の各枠1回・補充最大6回・初回を含む新規実行最大24回を維持する。再発しなければ初回18件＋補充1件の計19件となる。望ましい結果や品質不合格による追加はしない。

## 保存と分析

初回の `frozen-plan.json` と `batch-result.json` は変更しない。再開前のjournalを複製しハッシュを記録した上で、同じjournalに再開・回収・新規dispatchを追記する。再開後の終了結果は別ファイルに保存する。初回の研究コードハッシュは保存したまま、新しい再開用計画に使用する研究コードのハッシュを固定する。通常の実行器と評価器のハッシュ検査を維持する。

旧6 Run・初回18枠・補充を分ける。中断前後の区間を台帳に示し、時間要因の可能性を報告する。人の抜き取り確認はまだ未実施であり、探索後に材料を更新する。既に判明した preload-001 の表示不具合と評価器のファイル名判定への疑義は残す。今回の凍結評価器は変更せず、確認実験に進む前の解決事項とする。
