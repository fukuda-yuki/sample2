導入日: 2026-10-03（JST）。対象: **sample2の研究管理側Codexのみ**。
ユーザーから候補の判断・導入と、分析/考察に限定した運用整備を委任された。
共有会話「Codexプラグイン確認」（`6ac0959e-aa4c-83ee-8e09-dd4424440f73`）を候補の
出発点とし、公開リポジトリの原本・ライセンス・依存関係を確認して選定した。
会話内のスター数・推薦・普及度は採用根拠にしていない。

## 採用したもの

| Skill | 採用理由 | 使用場面 |
| --- | --- | --- |
| K-Dense `scientific-critical-thinking` | 証拠と主張の対応、測定/統計、致命的欠陥と限定的弱点を分けられる | 取得済み結果の分析・考察の基本 |
| K-Dense `hypothesis-generation` | 観測と仮説を分け、競合説明・識別予測・反証・探索/確認を記録できる | 結果の説明、次に何を調べるか |
| K-Dense `scientific-brainstorming` | 初案、反対証拠、少数案、基準、再発散、選択理由を保持できる | 次段階の方向を複数案で比較 |
| Orchestra `creative-thinking-for-research` | 問題の再定式化、制約、抽象度、構造的類推で現在の設計から視野を広げる | 問い/対象を捉え直すとき |
| Orchestra `brainstorming-research-ideas` | 問題先行/手段先行、失敗境界、単純な対照、関係者視点を補う | 方向転換や見落としの探索 |
| ACM SIGSOFT General / Benchmarking / Engineering Research | 方法に適合する研究基準で、過剰な否定を含めて点検できる | 専用Skillの固定参考資料 |

- **ARS（Academic Research Skills）**: 原本のdeep-researchは13-agentの文献調査中心、

  今回の分析専用範囲には広すぎ、工程間の確認・共有資材・他Skillへの依存も多い。
  ライセンスはCC BY-NC 4.0。今回のMIT採用群より用途・再配布条件も限定される。
  過去miscへの配置と、sample2での認識/使用実績は別。今回旧環境から移植していない。
- **STORM / Co-STORM、PaperQA2**: 文献調査/統合用の別アプリ・Pythonパッケージ。
  分析判断のSkill導入だけで足りる今回、別サービス・実行環境を増やす必要はない。
- **Google DeepMind Co-Scientist**: Codexに配置するSkillではなく別システム。
- **Superpowers、全Skill集、autoresearch/自動実験ループ**: 研究結果の考察専用という
  要件への追加価値が不明、または実装/実験実行へ範囲が広がるため導入しない。

## 配置・ローカル適応

`.agents/skills/`にリポジトリ単位で配置した。ユーザー共通のSkill/config、MCP、
OpenCodeのplugin設定、モデル/評価器/プロトコルは変更していない。
新しいパッケージ、外部API、アカウント設定、実験実行は不要。

各採用Skillの`SKILL.md`は分析専用に狭めたローカル入口。元の`SKILL.md`は同じ
フォルダの`UPSTREAM.md`に原文のまま保存し、必要な参考資料/テンプレートとMIT
ライセンスを同梱した。SIGSOFT基準も原文とCC0ライセンスを固定保存した。
原本commit・ファイルhash・ローカル入口hashは[manifest.json](manifest.json)に記録。
自動更新しない。更新時は原本差分・用途・ライセンス・入力分離を再点検する。

ローカル適応で優先すること:

1. **起動を取得後の分析・考察と、それに基づく次段階の判断へ限定する。**
   サンプリング/監視/停止/復旧/回収/共有や基盤修正だけでは起動しない。
2. 元資料の実験設計・実施案は結果の解釈と将来案の比較に使い、実行許可にしない。
3. 対話例・human-first・最終human判断は、今回の明示的委任を取り消さない。
   Codexは判断を進め、既読情報や人間による独立検討の有無を正直に記録する。
4. K-Denseの臨床評価基準・規制例は分野への適合を確認する。ソフトウェア研究には
   SIGSOFTを優先し、チェック数を妥当性の点数にしない。
5. Orchestraの歴史例・普遍的な創造性/新規性の主張は検証済み証拠と扱わない。
   特に「情報理論の限界を超える圧縮」などを事実として引用しない。
   類推から得るのは検証対象の予測。新規性だけで再現研究・負の結果を排除しない。
6. 元資料のCLI/生成図/別Skill/外部サービスは今回未導入。scriptsとCLIの説明専用
   referenceは除外した。保存したテンプレートは手作業での記録用に使える。
   `UPSTREAM.md`のコマンド例は実行可能な導入物一覧ではない。
7. 元資料に書かれた論文・出典・確認日は上流の記述。今回独立確認したとは称さない。
   研究成果に引用する場合は一次出典を確認し、利用できなければ未確認と明示する。
   ソフトウェアの帰属はmanifestの固定commitとライセンスで追跡する。

## サンプリングとの分離

既存の`outer/runtime/Dockerfile`はworkerへ研究リポジトリ全体をCOPYしない。
`outer/harness/runtime.py`のworkerマウントは各Runのinputs/workspace/stateであり、
研究ホストの`.agents/`や共通Skill領域をマウントしない。
catalog入力の準備も抽出物と既存の単一ツールに限定される。
さらに`.dockerignore`で`.agents`と研究者用AGENTS.mdをビルドコンテキストから除外した。
これは入力の分離を補強する設定であり、worker実行条件を変えるものではない。
この導入のために凍結版やimageを作り直していない。

手動でエージェントをRunに使う場合も、研究リポジトリをそのまま作業場所にせず、
条件で許された入力だけを持つ隔離workspaceを使う。研究用SkillやAGENTS.mdを
渡すことは実験条件の変更になる。

## 読み込みと検証の区別

この導入はファイルに基づくCodex Skill配置であり、ChatGPTのプラグイン接続ではない。
作成前にこのセッションのSkill一覧には採用群がなかった。配置後の自動認識は
ホスト/次セッションの再読込に依存するため、自動発動済みとは断定しない。
AGENTS.mdから明示パスで読む導線を用意した。
2026-10-03の配置後のexecutor Skill一覧は空だったため、このセッションでの
自動認識は未確認。以後は作業先をsample2にして、そのAGENTS.mdから入口を読む。

適用の例（運用ルールであり、自動ルーティングの実行試験ではない）:

| 依頼 | 適用 |
| --- | --- |
| 「取得済み100ペアの結論は妥当か」 | research-analysis → scientific-critical-thinking |
| 「なぜ品質/tokenにこの差が出たか」 | 上記にhypothesis-generationを追加 |
| 「結果を踏まえて次の研究を複数案で考える」 | scientific-brainstorming、必要ならOrchestraの2つを追加 |
| 「固定計画で次のペアを取得/監視/復旧/共有する」 | 起動しない。既存の実行手順に従う |
| 「保存ログを抽出する/基盤の不具合を直す」 | その作業だけなら起動しない |
| 「取得を終えてから結果を考察する」 | 取得を終えた後の考察部分だけ適用 |

構成・hash・参照と入力分離をオフラインで検証する:

```bash
python docs/research-skills/verify.py
```

このコマンドはモデル・Docker・評価器・ネットワークを起動せず、原データを読まない。
導入時の結果は[validation.json](validation.json)。固定上流原本との43ファイルの
byte一致と、変更前HEADの実験関係22ファイルとの一致も確認した。
静的検証はSkillの自動発動や研究判断の品質を証明しない。実際の分析依頼では使用Skill・
読んだ資料・行った工程を報告へ記録し、重要な前提の発見、競合説明の識別、
過剰な結論/不要な再取得の抑制に役立ったか確認する。取得の実行中にこの評価を行わない。
