## 次の主仮説を1件に絞る

**カタログ原文をファイルに保持し、モデルへの返却を必要な確認情報と所在に限定すれば、
要件を保ちながらRun当たり総トークンを減らせる。** これを次に検証する主仮説とする。
理由は、複数条件の新規反復でも大出力保持を観測し、短い機械処理結果を返す具体例も得たためである。
これは効果が確認できたという結論ではない。短い自然発生出力と小さい総量との対応は交絡を含む。

今回の追加分類・意味の注記は事後分析として残す。採取前のH2から対象を絞った介入であり、
先に大量の条件を試して最少トークンのものを採用したわけではない。
起動ログ量、プロセス終了の反復、ツールのまとめ方は候補として残すが、次の比較では同時に変えない。

主仮説の選定と、本実験の開始許可は別である。必要事実の対応表、品質評価の不一致、
人の確認を解決し、比較条件・標本数・停止規則を固定してから新しく計測する。

測定上の未確認も残る。新規3件・補充1件には、履歴の保持と送信文字量増加にもかかわらず
provider報告の入力tokenが大きく減る遷移がある（報告本文・`provider-input-decreases.json`）。
報告model IDの不一致ではないが、内部算定は不明であり、減少を文脈圧縮や効率化と推定しない。
確認では原本の文字量・保持とusageを併記し、この形式変化の扱いを採取前に定める。
provider内部の処理を確かめられない場合、結論は同じAPIの報告tokenに対する効果に限定する。
訂正時の全1,277呼び出しの再確認では、4箇所の減少と最終usageのキー・型の形式切替が一致した。
主指標はprovider報告input＋outputとし、形式切替があるRunも主解析から除外しない。
形式別・切替有無と送信文字量・保持量の補助分析を採取前に固定する。
形式切替の発生、数値の減少、provider内部の原因はそれぞれ別の主張として扱う。
詳細は[訂正報告](ms1-correction-20260919-report.md)と、その全件形式表を参照する。

## 具体化する比較案（未実装・未実行）

問いは「カタログの原文全件をモデル文脈へ入れずにファイル上で保持すると、必要な順序・IDを
保ったままRun全体のトークンを減らせるか」とする。起動ログ抑制やツールのまとめ方は同時に変えない。

| 項目 | 次に固定する内容 |
|---|---|
| 共通の準備 | 同じCompleted原本から、同じ決定的な抽出処理で順序付きデータを作る。モデル外での推測やLLM要約はしない。原本と抽出物を同じパス・同じバイト列で両条件へ供給する |
| 共通の情報 | 原本の所在・SHA-256・処理結果・10ジャンルの件数・246件・指定IDの検査結果・登録順を保った旨を、同一の短い出力として渡す。範囲指定で原文を取得する経路も両条件で同一にする |
| 変えるもの | 当該ツール結果にカタログ原文の大出力を併記する条件と、共通の短い出力のみを渡す条件。提示のタイミングとその他の出力は揃える。原文側の対象範囲・表示上限・切詰め規則は採取前に固定し、全文取得したと誤記しない |
| 固定するもの | タスク、要求、モデル、エージェント、予算、compaction、ソース、準備処理、ツールと出力上限、原文アクセス、改版・校正済み評価器。新しい情報処理機能は両条件に同じものを与える |
| 主指標 | 全呼び出しのinput＋output、失敗・打切り・欠測を含む全試行。準備が決定的な非LLM処理ならLLM tokensは発生しないが処理方法と時間は記録する |
| 行動の予測 | 初期の大きな入力増分とその後の保持文字量が小さくなる。原文再取得・呼び出し数・後半修正が増えて効果を相殺しない |
| 反証となる観測 | 全文再取得で入力差が消える、追加の確認／修正で総量が減らない、必要なID・順序・文字列・購入挙動を失う、別の追加情報の有無だけで差が説明される |
| 品質条件 | 既存挙動・データ制約との対応を先に確認。原本の削除や勝手なソートはしない。要件の品質低下があれば効率改善と判定しない |

この比較は現行3条件の勝者選びではなく、観測された入力増加に対応する特定の変更を検証するもの。
短い出力側にだけ設計上のヒントを加えないことが重要である。
具体的な共通出力、取得手順と範囲、期待する必要事実は、確認用データを採る前に固定する。
今回の53,025文字のread結果は50 KB上限の表示で、例としてCompleted原本の1〜360行が見え、
361行以降の取得を促す注記がある。これは全文ではない。ツール出力の切詰めと会話文脈の圧縮を分け、
基準条件だけ表示上限を拡張したり、短い条件だけ原本アクセスを制限したりしない。
共通の抽出処理を持つ新しい2条件の比較であり、既存exploreと短縮条件を直接比較して
「返却量だけの効果」と主張する設計にはしない。今回この補助処理や介入は実装していない。

## 確認実験の反復数と停止

今回は反復数を決めない。まず、実務上意味のある最小削減幅、許容する品質低下の上限
（低下を許さない場合はその判定法）、推定に必要な精度、総実行予算を定める。
その後に、ばらつきの保守的な範囲を使って、固定反復数で得られる精度や検出可能な差を検討する。
探索の条件平均や最少値から得た削減率を真の効果量として採用しない。
解析法・順序・技術失敗の扱い・追加／停止規則を採取前に固定し、新しいRunだけで確認する。
途中の結果を見て有意になるまで追加しない。
[反復数の正当化](https://lakens.github.io/statistical_inferences/08-samplesizejustification.html)

## 先行研究との位置付け

タスクに必要な文脈を選別する問題は
[SWE-Pruner](https://arxiv.org/abs/2601.16746)でも扱われている。
本候補は、カタログの登録順・ID・注文挙動を保つモダナイズにおいて、データをファイルに保ち、
モデルへの提示範囲を変える場合の成立条件を調べる案である。
既知の選別効果の再現なのか、データ制約のある課題への拡張なのかは未確定で、
題材の違いだけを新規性とはしない。論文の削減率を今回へ移し替えない。
